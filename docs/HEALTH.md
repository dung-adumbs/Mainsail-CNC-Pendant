# Hardware health monitor

Requires matching `cnc_health.py`, updated `cnc_preflight.py`, the health UI asset and this owner's reviewed lamp macros. Disabled by default; `health_enabled: true` in `[cnc_preflight]` enables it. Do not enable without reviewing the pause workflow and lamp configuration on the actual machine. The example lamp macro is specific to the existing white work light and animation timers, not a generic pin definition.

Pi temperature at the shared `cnc_pendant.temperatureWarning` threshold (default75°C, clear2°C below), current Pi undervoltage/throttling/soft-temperature flags, and supported TMC driver `otpw`/`ot` flags qualify. Historical Pi flags do not. CPU activity, MCU awake time and scheduled motion ahead are informational. MCU awake percentage uses the five-second Klipper reporting interval. Missing/disabled driver status is unavailable, not healthy; no numeric driver or motor temperature is invented.

The Pi-owned one-second monitor uses a ten-second persistence window; gaps greater than three seconds reset the countdown. Pi system statistics are sampled at most every two seconds. This integration currently uses Moonraker's installed proc_stats handler and must be rechecked on upgrades. No per-move disk writes. An automatic pause uses the existing PAUSE workflow, with its queued motion, lift and capture behavior. Faults already handled by Klipper retain immediate shutdown behavior. A sudden host failure can also prevent this monitor from running; this is not an independent safety controller.

An active qualifying warning flashes the white work light at approximately3.3 full cycles/second even if it was off. Existing lamp animation timers are temporarily suspended and restored on clearing; idle/stepper policy is not disabled. User lamp commands may briefly affect a phase before the next warning tick. Lamp effects may not run after Klipper shuts down. Controller restart also clears live lamp state.

The normal indicator is green, warning amber/pulsing, faults red, unavailable/stale gray. Both compact jogging and the running-job view offer the same status dialog with highlighted readings, Pause now and explicit acknowledgment. Acknowledge is disabled while warnings or required missing readings remain. No automatic Resume. The pause latch/reasons persist in Moonraker database namespace cnc_health and block Pendant's backend Start/Resume until cleared and acknowledged. Existing file/hash/position/keep-out checks still apply afterward. This gate covers Pendant preflight execution; native Mainsail/raw console commands are not a globally enforced Klipper interlock and must not be used to bypass it. Broader enforcement remains separate work.

Prepare and test all source, lamp templates and UI before activation. Save original paths/hashes and coherent configuration dependencies. Activation requires Moonraker reload plus Klipper restart to load the new macro/include, clearing homing/work references; obtain explicit approval and require idle state first. No physical fault or motion should be induced for software tests. Keep a physical stop available for operator testing. Rollback requires hash conflict checks and preserving newer edits before coherent restoration; restored software cannot restore physical references.
