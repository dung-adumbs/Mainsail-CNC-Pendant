# Tool checks and travel defaults

Combine & set travel speeds and Continue travel settings use the same preparation flow as direct travel optimization. Travel-rate inputs appear before heavy processing. Previous project rates take precedence, then shared defaults; initial values remain the existing3000mm/min XY and180mm/min Z retract. These are starting values for review, not certified safe rates. The existing backend still checks machine velocity/override ceilings.

Preview reads tool definitions from the actual source bytes. Tools marked CHECK BEFORE USE, UNVERIFIED, provisional, draft, unknown or similar attention descriptions require physical-tool confirmation. Missing essential geometry also requires attention. Tool type, cutting/shank diameters, flute/overall lengths and flute count must be present and valid; ball/taper tools additionally need valid radius/angle data. Missing data cannot be acknowledged away: correct the definition in Fusion and repost. Older posts without full Fusion operation/tool metadata may therefore need reposting before optimization. Original staging paths are unchanged by this UI preparation gate.

The dialog shows stored specifications and requested RPM, with an unchecked physical-suitability checkbox. Continue remains disabled until confirmed. Cancel stops preparation before consolidation/upload. Identical definitions used again are reviewed once per preparation; different geometry under the same tool number is reviewed separately. Text is rendered as text, never interpreted as HTML. Confirmation does not edit/promote a Fusion library tool or establish a measured router dial/RPM calibration.

Project consolidation rereads and hashes sources, requests review before compile/upload, and stores source-bound tool acknowledgment with the project. The optimizer preview's source hash must match the reviewed source; a mismatch disables creation and requires another review. Backend preview/create hash protection remains authoritative. Preview, Create copy, Stage/verify and explicit Start remain separate actions. This does not yet replace the running tool-change dialog or impose a global raw-G-code/tool interlock.

Chosen rates and tool review are saved with the project output. Remember these as my shared travel defaults is optional and saves only after creating an output. Shared preferences travelXY/travelZ are scoped to this machine's Moonraker database; they are not universal machine settings. No cutting-feed or geometric changes are introduced by the review UI, and no job starts automatically.
